# Latin PR cues — operating note

This note describes the handoff between manual comments and the installed recorder; the [canonical glossary](../../docs/latin-workflow-glossary.md) defines the terms. It does not create a second glossary or authorize a merge. See [`guides/pr-lifecycle.md`](../pr-lifecycle.md) for the existing review/finalize/merge sequence.

## Installed now

- `.github/workflows/latin-cue-record.yml` (merged in PR #367) listens to newly created PR conversation comments. Its cheap event prefilter checks for one of Recensio, Probatio, Lustratio, Judicium, Novissimum or Cursus in comments from OWNER, MEMBER or COLLABORATOR-associated non-bot users; then the script extracts whole-word calls and adjacent modifiers including Renovata and Expeditus.
- The script ignores cues in fenced code, inline code and quoted `>` lines, and skips a comment carrying the `Generated by [Claude Code]` footer. It writes or updates one cue-record comment with the PR state, checks and comment links. It does not call a model, review, finalize or merge.
- **Important limit:** the actor association or `Eaprime1` login alone is not a proof of Eric's personal intent. A navigo reply can appear under the same account. The footer guard covers a known case, not every future tool or handoff format. Do not treat the cue record as an authorization or as a decision.
- Separately, the *explicit* `@claude ultima Probatio` or `@claude finalize` cue can activate `.github/workflows/finalize-pr.yml`. Never paste it as an example in a live PR comment unless finalization is intended. Merge remains a separate Eric-requested action.

## Human cadence proposal

For a PR, Eric can ask for a bounded Recensio and a later Probatio; Lustratio is optional when presentation or provenance needs it. Renovata requests a refresh after meaningful new work; Cursus expeditus requests the applicable finish steps in order, without waiving required checks. These are human workflow preferences, **not** a machine-enforced once-per-phase limit. A review receipt records what actually happened.

## Differences to test before expanding automation

- There is no dedicated opt-in marker: prose containing an unquoted call can be recorded if the event prefilter and parser match.
- Several different calls in one comment are logged together rather than asking Eric to choose one.
- There is no durable deduplication ledger keyed by source comment ID beyond the current one-comment upsert; repeated owner instructions are logged as separate events.
- The footer guard is specific to one navigo output format. Test other agents' GitHub author identities and signatures before claiming all spurious triggers are prevented.
- A record of a call is not proof a review was performed. No added paid review or automated merge should follow from this file alone.

Use real, consented comment examples to test quote handling, bot/owner differentiation, repeated calls and the explicit finalize gate in a dedicated test PR before expanding any automation.
