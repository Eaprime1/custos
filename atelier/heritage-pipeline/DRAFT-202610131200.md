## 2. What "nullification copy" means (reconciled with the NULLUS canon)

Read in `Eaprime1/nullus` (verified): `docs/glossary.md` says nullification moves an entity toward
`fui nullus` (existed, as naught), not `non fui`, and that "the distressed state is made naught —
not erased." It defines the process as a distressed pattern **replaced by a transformed version**,
the entity continuing with the lessons carried. `docs/emergency-protocols.md` asks for a record of
what was nullified and why.

So, for a document:

- **B (live copy):** each distressed lexeme is replaced by a transformed pattern, and the replaced span is marked as nullified. The live copy does not carry the distressed text.
- **The record:** a replacement log (span, replacement, reason, SHA-256 of the original span) sits with the origin, never in the live copy.
- **A (origin):** untouched. Nullification never deletes the origin.
- The "as if it never was" language in the NULLUS package is narrative; the file system keeps the origin and the log. *The Shepherd to confirm this reading.*

## 6. Grading: a quality baseline, bounded numbers (proposal)

The Shepherd's point: this group creates well, so high quality is the baseline, and most value systems drift into huge numbers.

Verified from the code and the run:

- The collapse engine computes `€C = words × 0.05 + TKP × 20` and `Ξ = words / 30 + TKP × 10`. Value grows with length alone. The Sanctum run gave **851.0 €C and 564 Ξ**. A 150-word note at the same TKP gives about 27 €C, so padding raises the number.
- The makers engine's `€C` also scales with word count.
- TKP hits its 0.99 cap on this text and its 0.50 floor on a plain paragraph (§ Engine tests below).

Proposed principles:

1. **Gate first, score second.** A pass/fail checklist for the facts that matter: provenance kept, canon labels present, seeds verbatim, hash reproducible, origin archived. Failing any item means no score.
2. **No length term.** Words never raise value.
3. **Bounded and banded.** Ranks stay on the card scale; a score is 0 to 10 and nothing above.
4. **Small numbers.** If a currency figure stays, it is reported as a band, not a figure to the decimal.
5. **Watch the distribution.** Each ledger reports median and maximum so inflation shows up early.

## 7. Engine tests (verified 202610131200, on a text extract of the 86-page Sanctum PDF)

| Finding | Evidence |
|---|---|
| The collapse engine's own output fails the makers engine's check. | `collapse` then `verify` on the PR Journey gives **TAMPERED**: recorded `b5f03098aa`, expected `c5a866752d`. |
| Cause: the two engines normalize text differently. | The makers cleaner reads the `---` rules in the body as YAML front matter and removes the text between them (2124 characters become 1452). The collapse engine hashes the body with a plain `strip()`. |
| TKP cannot tell texts apart at the top. | The Sanctum text scores **0.99**; a plain paragraph scores 0.50. The 0.75 gate passes any text with enough headings and symbols. |
| Automatic seeds missed the real ones. | Five seeds, all chamber descriptions. None is `suxens_stone`, `shadow_road_pressure` or `return_to_prime`. The SOP asks for 1-3, hand-picked. |
| Seed timestamps are processing time. | `timestamp_utc` is the run time, not when the conversation happened. |
| The journey text claims things that were not done. | Generated lines say monitoring is active, withdrawal is engaged, and findings were "harvested into ... permanent storage." |
| Title and ID are rough. | The title came out as `## I. Transition from Discovery to Heritage`; the ID comes from the file name. |

Repro, from a scratch folder: copy both engines, run `python3 -I conversation_collapse_engine.py collapse <text> -o out`, then `python3 -I makers_mark_engine.py verify out/<id>_PR_Journey.md`.
