# What to expect: PR and content processing (DRAFT)

**Filed in custos:** 202611010342 UTC, atelier. Written for Eric by navigo_claude.

For Eric, who moves between places, reads in bursts, and gets interrupted. Pace is yours. Nothing here is a deadline.

## How I work with you
- **Step by step.** One PR or one item at a time. The first run is hard and sets a pattern that is real, not perfect.
- **Direct questions.** Where I need you, I end with one question, or a ready-to-paste prompt message. Waiting for you costs nothing.
- **No quality drop** when you are slow to answer. I hold state and say where we left off.
- **Review noise.** Bot comments (Codacy, DeepSource, Shepherd Considers) come in bursts. I will not chase each one; I batch them and report only what needs you.

## For each PR I report one line
`#N · state (draft/ready) · checks · labels · ready / blocked-by-what / needs-your-word`
Posted where all voices find it: a Jira comment under the NEXUS-1 child task, plus the PR where fitting.

## What I will not do without your word
Seal, merge, set `ready-for-oversight`, send the Armarium pack, push to a branch that is not mine, or post an owner cue.

## The baton (so nothing is lost)
Errors, gaps and issues are opportunities; we cannot take all. Each one I meet gets a one-line entry: **what / where / who holds it next / destination**. It is handed on, not dropped. Handing on is a deliberate act, so the primary focus stays and no find is lost.

## PR subscription
I can subscribe this conversation to PR events (reviews, CI, comments). On a busy list that is a lot of wake-ups. Suggested start: the PRs we are actively moving, not all 31.

## When I am unsure
I say so, mark guesses as guesses, and never invent stamps, ids or history.
