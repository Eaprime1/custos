# Bit Germ Dust — A Contributor On-Ramp for Fringe/Bot Submissions

*nursery entry, filed 202607212051 — nothing here is finished*

## The pattern this responds to

Submissions keep arriving that don't fit the normal mission/bounty flow cleanly — something that reads like a bot fishing for anything to do (a recent Linear submission had this shape), or a fringe contribution that only worked because custos adapted to it as it came in rather than the other way around. This isn't rare. It happens often enough that it's a pattern, not an exception.

The current options for these are essentially binary: fold them into the formal mission/bounty system (often too heavy for what arrived), or let them pass without real engagement (which wastes a genuine, if unfocused, offer to help). Neither serves the ethic already written into this repo's own PR template: *"Free to fork, remix, echo — no hidden ownership."*

## The idea

**Bit germ dust**: a small, always-available, ready-to-hand task — a germ, in this repo's own vocabulary (see `pandora/GERM_SCHEMA.md`) — that custos can generate close to on demand. Eric's framing: "I can always (almost) find something." When a fringe or bot-shaped submission arrives, custos hands them one of these along with interaction options, rather than a formal mission brief or silence.

**The reward gate stays real**: a bit of germ dust is an invitation, not a credential. To actually earn a **sparstone** (the existing award-taxonomy term — see `incoming/pre-nullus/`'s Sparstone references), they still have to complete a genuine custos mission. The germ dust doesn't shortcut that. It's the on-ramp, not the destination.

**No pressure either direction**: if they engage, good — that's the Flock growing. If they don't, that's fine too — nothing was promised, nothing is owed. This is explicitly meant to hold to custos's existing participation ethic, not create a new obligation.

## Why this belongs in pandora, eventually

`pandora/README.md` already describes itself as "a container branch for cross-conversation germs." Bit germ dust is a specific *use* of the germ concept — a germ generated specifically to be handed outward to an unscoped or fringe arrival — rather than a new container. Worth building as a mode of pandora rather than a sibling system to it.

## Open, not decided

- What actually generates a germ on demand — a template bank, a script, custos itself reasoning it out per-arrival? Not scoped yet.
- Where the interaction options get delivered — PR comment, issue reply, something else?
- How "fringe or bot-shaped" gets recognized in the first place, versus a normal mission/bounty submission. No detector proposed here — this seed assumes a human (or Claude, on request) is still the one noticing the pattern.
