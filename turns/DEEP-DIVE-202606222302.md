## 1. What a visitor sees first

### Root directory is cluttered
Alongside the expected `README.md`/`CLAUDE.md`/`prima.yaml`, the repo root currently also has:
- `seneschal.md` + `seneschal-v2.md` — two competing drafts of the same character, landed at root instead of `world/` or `atelier/commissions/seneschal-exploration.md` (which already exists and is the proper home).
- `gemini-code-1781930306290.md` + `gemini-code-1781930323398.md` — Gemini's self-introduction and journey-log, clearly meant for a `.gemini/` directory (parallel to `.claude/`, `.codex/`, `.sovran/`) but never moved there.
- `The First Sparklization Journey.docx` (3.0 MB) and `the-first-sparklization-journey.jpg` (1.1 MB) — large binaries sitting at root with no index or context.

None of this breaks anything, but it's the first impression. **Build item: relocate these into their proper homes** (`world/seneschal.md` picking one draft, `.gemini/identity.md` + `.gemini/journey.md`, and the binaries into a `media/` or `valuation/` subfolder with a one-line pointer from wherever they're referenced).

### GitHub Pages is silently deploying the raw repo
`.github/workflows/static-gh-pages.yml` fires on every push to `main` and uploads the **entire repo root** as the Pages artifact — no build step, no `index.html`. If Pages is enabled in repo settings, visitors hitting the Pages URL get an unstyled directory of markdown source files (including the loose root clutter above, and potentially the `.docx`/`.jpg`). **Build item: either give this a real landing page (render README as the index) or disable the workflow until there's something worth shipping there.**

### README and CLAUDE.md are in good shape
Both are current, descriptive, and match the actual repo structure (verified by walking the directory tree against README's "Repo Structure" block — accurate). No drift found here.

## 2. Lore/scaffold vs. interactive

The repo is heavily weighted toward **world-building documents** (character sheets, faction lore, journey narratives) relative to **things a visitor can actually run**:

**Things that work today, as-is:**
- `tools/thee.sh`, `tools/yod.sh`, `tools/ember.sh` — the intake triad, functional bash scripts
- `tools/prime_check.sh`, `tools/scan_lexeme.sh` — state/validation tools, functional
- `tools/log_install.sh`, `tools/seneschal_audit.sh`, `tools/artesian_scan.sh`, `tools/valuation_report.sh`, `tools/check_mission.sh` — functional utility scripts
- `seeds/bootstrap.sh` — idempotent environment bootstrap
- `quests/000-thee-the-door.md` — has a real deterministic Completion Check

**Things that are pure narrative/scaffold with no executable surface yet:**
- `dungeon-master/` — full directory structure (narrative-engine, chronicles, quests, expeditions, pr-harvest, registry) but, per its own Phase 1 turn entry, "no automation wired — structure only." One seeded chronicle exists; nothing generates the next one automatically.
- `atelier/` — 19 files, all explicitly unfinished by design (nursery), several with no clear next step (`concordance.md`, `wobbly-bench.md`, `ouroboros-wobble.md`, `testing-lab.md` — all flagged as unfinished concepts as far back as the 2026-06-21 mining pass and still unfinished now)
- `.agents/`, `.codex/`, `.sovran/`, `.claude/skills/` — identity/config files for multiple AI tool integrations, but no evidence any of them have been exercised end-to-end (no turn log entry references a session run through `.codex` or `.sovran`)
- `returns/stream-6-grok/`, `returns/stream-7-perplexity/` — empty, domains still TBD (carried forward unresolved since at least PR #38's era)

**Read on "ready to interact":** the repo has a strong identity and a real (if small) set of working CLI tools, but the bulk of recent growth (PR #111/#115, dungeon-master, atelier commissions) has been narrative content describing systems that don't yet execute themselves. The THEE/YOD/EMBER triad and prime_check are the only things a true newcomer could run in under a minute and see a result.
