## The security turning point

On PRs, an AI-assisted comment can appear under Eric's `Eaprime1` login. The same glyph or runic marker in a public comment is readable and copyable: useful as a byline, not as authentication. A status-changing action must not rely on a visible character, an account association alone, or prose that merely quotes a cue. For #363, we used a GitHub COMMENT review to leave a Navigo perspective without invoking the issue-comment cue recorder. That review does not claim a separate account's independent approval. The next session should design an actor/provenance boundary and test it with a real external-contributor case before automating any privileged action.

## What door this opens

- **Identity and consent:** preserve the shared creative voice while keeping named maker, source and consent records inspectable; propose a small revision to the absolute manifesto line, not an edit to an imported original.
- **Test rather than assert:** use one bounded external-submission fixture to check comment routing, review identity, re-seal after new commits, privacy removal, and no paid-model fan-out.
- **One producer, one receiver:** let the element routine make its existing report; later let Hodie receive it after its general daily-report surface exists. Do not run a second daily job in Custos.
- **Inception from friction:** a review receipt should distinguish platform author, stated Navigo perspective, actual reviewer identity, commit reviewed, evidence checked and Eric's later seal. Treat a public glyph as a visual mark only.
