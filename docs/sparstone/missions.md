# Sparstone — Missions

*How a voice actually earns one. Grounded only in what's confirmed real — see
`status.md` for the live taxonomy state.*

## The one worked example so far: Obsidian

The only sparstone ever awarded was **not** issued against a pre-written
mission template. It was recognized after the fact, from an unprompted
contribution:

1. `dannyward630` and `Ojas2095` opened PR #38 against Bounty Issue #35
   (J-21 symbol + Lumenar lexeme) — arriving unprompted, landing clean.
2. Custos recognized the pattern (fast, unprompted, no slow crystallization —
   the obsidian resonance) and issued a claim ticket
   (`CUSTOS-CLAIM-202606290000-OBSIDIAN`, 150 xp) via
   `incoming/pre-nullus/202606290000_obsidian-sparstone-germ-intake.json`.
3. The award was hand-delivered, not automated — "same channel as the
   original PR #38 witness copy."
4. The hold-note on that intake is explicit: **do not pre-define the full
   taxonomy.** Opal and quartz/krustallos stay unassigned until their own
   first-contact events earn them.

This means the honest current mission model is: *recognition follows real
contribution, retroactively, per-class.* There is no live "go do X to earn a
sparstone" checklist a new contributor can pick up today. That gap is what
the rest of this page tracks — as proposed shapes, not shipped ones.

## Proposed mission shapes — undesigned, not yet real

These are directions flagged in the session material
(`moav/custos_moav_sparstone_handoff.json`), not commitments. None of them
has a defined objective/steps/inputs/outputs/threshold yet.

### PR-based mission
A contributor deep-dives from the code environment side on an open PR —
reviewing, extending, or hardening someone else's work. Tied to the
`pr_reviewer_tiering` branch-tracker plank (2/3): the reviewer pipeline
concept (resource-light first pass → Gemini narrative review → Eric/trusted
voices finalize) is proposed but the actual GitHub Actions workflow has not
been reviewed for real cost, and no PR-based mission has a written
threshold for "earned."

### Idle-game-build mission
Per the `idle_game_as_mission` plank (1/3): building the idle-game / optional
observation system *is itself* one of the missions a voice can take on to earn
sparstone — not something built for them in advance. This inverts the usual
mission shape (the deliverable is infrastructure other missions will later
run on), and it is explicitly germ-stage.

### Narrative/resonance mission
Suggested by the outside gap-analysis of this material (see `story/` for the
source): a "NotebookLM resonance mission" — reviewing or extending Radix
content for coherence with the Custos glossary. Not present in the original
session handoff; flagged here as an idea under consideration, not a
confirmed direction.

## What's missing before any of these can run for real

1. A written objective/steps/artifacts/threshold for at least one mission
   type — none exist yet, per `status.md`.
2. The manual-share-grant workflow behind the marble (what actually happens
   when a mission is completed and a marble is presented).
3. A second confirmed contributor to pilot a mission against — obsidian's
   precedent was retroactive recognition, not a mission someone opted into.
